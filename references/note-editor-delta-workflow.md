# 差分改稿とカード確認

既存本文への短い改稿は、15分程度を目標に差分で進める。15分経過を失敗や公開承認に読み替えない。調査・新規実装が必要なら本務と分け、理由と残務を明示する。全記事の編集を15分以内と保証しない。

## 既存の状態から始める

タブ一覧と選択中タブを一度取得する。同じNoteが複数開いていれば、選択中の本人稿を読み、旧タブやローカル稿で上書きしない。対象URL・本文・カード・画像・見出し・リンクのbeforeを既存実行receiptへ保存する。変化のない全文やskillを毎操作読み直さない。

短い一周の目安は、現稿と差分の確定2分、本文修正5分、カードと画像4分、保存と読戻し4分。未完了の外部widgetは再挿入せず、対象を特定して報告する。既存の必須履歴検査は省かず、変更した同一版に一度通す。

## 末尾カードを忘れない

選定の正本はhostの既存制作記録。前話や固定枚数だけから採用を推定しない。明示された同じカードの承認を取り直さず、URL・表示種別・理由を記録する。読み込み確認が必要なcardの選定linkへ`require_rendered: true`を指定する。

1. 現稿で対象`figure[data-src]`を数える。1件なら追加せず内容を検査、0件なら採用済み経路で一度挿入、複数なら入力停止。
2. 外部記事widgetの実タイトルと、そのanchorのhrefをDOMから取得する。`data-src`だけ、空widget、ローディング中は未完了。iframe型は対象iframe内のタイトルとリンクを実読取りし、取得不能なら未確認として残す。
3. 観測`footer.nodes`へ`tag: "FIGURE"`, `data_src`, `rendered: true`, `title`, `rendered_href`を実取得値から保存する。タイトル非空・href一致を確認した時だけrenderedをtrueにする。スクリーンショットでレイアウトとサムネイルを確認する。
4. `python scripts/note_editor_prepublish_verify.py <observation.json> --production-plan <既存選定計画> --footer-only --json`を実行する。これは供給snapshotの検査であり、実サイト検証や公開承認を発行しない。
5. 下書き保存後に同じカード・順序・前後本文を読戻す。公開や予約へは進めない。新しく本文を編集していない場合は、保存操作を増やさず現在の保存済み状態を確認する。

## 復帰の往復を減らす

- 既存guardを使う。書込みは対象1件ずつ、待機・DOM観測はまとめる。pending中は同じhandleのreconcileで読取り、再Applyや別factoryでの再送をしない。
- 適用clickはfresh AXで一度。dialog入力の可視化、挿入用空P、card IDの遅延は既存guardが扱う。外部描画の遅延で著者本文の保護を緩めない。
- 生URLの除去は検証済みの完全一致AX leafとRangeだけ。広いroot選択、P全体fill、全文再貼付けでの復旧はしない。
- 同一原因の修正と再検証は最大2回。共有コードの修理を本務の20件へ逐次混ぜず、最小smoke1件で経路を確定してから残りへ適用する。不確定な副作用があれば停止状態を維持する。
- コード無変更のカード1件確認に全テストを繰り返さない。コードを変えた場合は該当behaviorテストを一度実行し、失敗や新しい変更時のみ再実行する。
